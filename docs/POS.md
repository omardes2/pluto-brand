# وحدة نقطة البيع (POS)

البيع المباشر داخل المحل: بيع نقدي/بطاقة، وردية وصندوق نقدي، مصروفات يومية، إرجاع
واسترداد، وتقارير. مبنيّة **فوق الخدمات القائمة** (المبيعات/المخزون/المحاسبة/المرتجعات)
دون تكرار منطق — القناة `pos` كانت مُجهَّزة في التصميم منذ البداية.

## النطاق

| الميزة | الوصف |
|---|---|
| **البيع** | نقدي/بطاقة، خصم على الفاتورة (بصلاحية)، خصم مخزون فوري، إيصال 80mm. بلا ضريبة (`tax.enabled`). |
| **الوردية والصندوق** | فتح وردية برصيد افتتاحي، إيداع/سحب نقدي، مصروفات يومية، إغلاق وتسوية (متوقّع مقابل معدود + فرق). |
| **المصروفات** | سحب نقدي من الدرج بنوع (غداء/كهرباء/…) ومبلغ وملاحظات. |
| **الإرجاع** | بالفاتورة الأصلية: إعادة للمخزون (صالح) أو تسجيل تالف، استرداد نقدي من الدرج، عكس العمولة، تحديث حالة الطلب. |
| **التقارير** | أرشفة يومية: إجمالي المبيعات، النقدي، البطاقة، المصروفات، عدد الفواتير، الرصيد النهائي (صافي النقد). |

## المعمارية (إعادة استخدام بلا تكرار)

| يحتاجه POS | يُعيد استخدام |
|---|---|
| إنشاء طلب وبيع مباشر | `OrderService.create` (channel=pos) + `fulfillDirect` (ترحيل + خصم مخزون + تسليم) |
| حدّ سعر الجملة | `OrderService` (مطبَّق تلقائيًا لكل القنوات) |
| التحصيل النقدي | `OrderPaymentService.collect` → خزينة الوردية |
| كتالوج/باركود | `ProductVariant` + `InventoryStock` (المتاح = on_hand − reserved) |
| الإرجاع | محرّك المرتجعات `ReturnService` (RMA) بالكامل (create→approve→receive→inspect→complete) |
| المخزون | `InventoryService` (return_in / damaged) |

## المكوّنات

- **النماذج:** `PosShift` (وردية) · `PosShiftMovement` (حركة درج: opening/cash_sale/card_sale/refund/pay_in/pay_out بتصنيف).
- **الخدمات:** `PosSaleService` (بيع) · `PosShiftService` (فتح/حركات/مصروف/استرداد/إغلاق + النقد المتوقّع) · `PosCatalogService` (بحث/باركود) · `PosReturnService` (إرجاع يقود RMA) · `PosReportService` (تجميع يومي).
- **الواجهة:** شاشة كاشير ملء الشاشة (`/admin/pos`، Blade + Alpine) + شاشتا فتح/إغلاق وردية + إيصال 80mm + صفحة تقارير (`/admin/pos/reports`).

## الصلاحيات ودور «كاشير»

`pos.view` · `pos.sell` · `pos.discount` · `pos.refund` · `pos.refund.no_invoice` (مشرف) · `pos.shift.manage` · `pos.reports.view`.
دور **`cashier`** يملك القدرات الأساسية (بلا الإرجاع دون فاتورة ولا التقارير).

## تدفّق البيع (معاملة واحدة)

```
إنشاء طلب channel=pos مربوط بالوردية
  → fulfillDirect (تأكيد + حجز + شحن + تسليم: ترحيل محاسبي + خصم مخزون)
  → collect (تحصيل كامل في صندوق الوردية)
  → حركة درج (نقدي/بطاقة) + تحديث أرصدة الوردية
```

## النشر (بعد أي تحديث)

`deploy/update.sh` يشغّل الهجرات فقط. عند إضافة صلاحيات/إعدادات جديدة، شغّل البذر
(متكرّر وآمن):

```bash
php artisan db:seed --class=PosPermissionSeeder --force
php artisan db:seed --class=PaymentMethodSeeder --force
php artisan db:seed --class=SettingsSeeder --force
```

## ملاحظات / نقاط مؤجّلة

- **التبديل الذرّي** (إرجاع + بيع بديل + تسوية الفرق في عملية واحدة): النتيجة النقدية
  والمخزونية نفسها تتحقّق حاليًا كخطوتين (إرجاع ثم بيع بديل).
- **الإرجاع دون فاتورة** (`pos.refund.no_invoice`): الصلاحية موجودة؛ الواجهة الحالية
  تتطلّب رقم فاتورة (مسار المشرف الاستثنائي يُبنى لاحقًا).
- **استرداد البطاقة:** يتم فعليًا على جهاز نقاط البيع؛ النظام يسجّل الأثر.
